# AI Office / AI Ops — 프로젝트 노트

설계 판단, 사고, 실측 수치, 배운 점을 이 프로젝트 기준으로 쌓아두는 곳. 나중에 경험을 정리하거나 면접에서 설명할 때 근거로 씀.
공개 저장소이므로 **내부 시스템 이름·주소·키·개인 데이터는 적지 않음** (LLM 게이트웨이는 "사내 게이트웨이"로 표기).
형식: 날짜 + 한 일/판단 + 이유. 길게 다듬지 말고 겪은 즉시 추가.

## 1. 무엇을 만드는가

- 목적: 에이전트 루프를 **운영·관측·검증**하는 플랫폼(AI Ops). 픽셀 오피스(Office)는 의사결정자용 시각화일 뿐 실체는 Ops.
- 첫 워크로드: 자소서 writer ↔ reviewer 루프 (루브릭 채점 → 통과/재작성 → 사람 승인).
- 화면 2개
  - Ops(`/ops`): 개발자 콘솔 — 토큰/비용/예산, 프롬프트·응답 타임라인, 설정 스냅샷, 점수 차트, diff, run 비교, 큐
  - Office(`/office`): 의사결정자 — 결과/점수/중단 사유/비용 합계, 승인·계속·수정·반려, 연속 운영 on/off, Ops 팝업
- 스택: Python 3.14, FastAPI + SSE, LangGraph(조건부 엣지), pydantic v2, httpx, SQLite, 단일 HTML(빌드 없음), pytest, Playwright(브라우저 E2E)

## 2. 설계 원칙 (바꾸려면 이유가 있어야 함)

1. **run 기록이 단일 진실원.** 화면의 모든 값(상태·비용·점수)은 이벤트 로그에서 파생. 따로 저장하지 않음. 설정은 `run_started`에 스냅샷으로 박아서 과거 run을 재현·비교.
2. **AI는 run을 확정하지 못함.** 사람의 결정(approve/reject)만 run을 닫음. 점수가 높아도 마찬가지(→ 5장 실측 근거).
3. **계측 우회 불가.** 워크플로가 쓸 수 있는 LLM 핸들은 `MeteredLLM` 하나. 호출 전 **최악 비용 예산 가드**(입력 추정 `len(prompt)//2` + `max_tokens`, 설정된 최대 단가 기준)로 예산을 넘을 호출은 보내기 전에 거부.
4. **Office에는 프롬프트/응답 원문을 보내지 않음.** 합계·결과·점수·결정·활동만. Office 결정자는 서버가 `office`로 고정.
5. **측정 가능한 제약은 LLM 판단에서 빼고 코드로 보증.** (글자 수 등)
6. **라이브러리는 편집 가능, 실행은 스냅샷.** (데이터셋·프롬프트 설계 방침. 구현 예정)

## 3. 구조 지도

```
backend/aiops/
  core/   db(SQLite 단일 파일·트리거), store(실행 기록), metered(계측·예산 가드), engine(수명주기+승인 게이트),
          jobqueue(큐+워커), summary(로그→요약), config(RunConfig), pricing, jsonx, env
  llm/    base, fake(결정적 점수 시나리오), hchat(게이트웨이 클라이언트), factory
  workflows/  base(계약), cover_letter(LangGraph write→review→decide)
  office/ view(Office용 요약·활동 매핑)
  api/    app(FastAPI), static/ops.html, static/office.html
  dbio.py  텍스트 내보내기/가져오기
backend/tools/mock_hchat.py   로컬 모의 게이트웨이 (비용 없이 재시도/실패 경로 시험)
```

- 워크플로 계약: `run_pass(ctx) -> stop_reason`. 계측·기록·예산 상태·승인 게이트는 코어 책임, 워크플로는 루프만.
- 상태 파생: `running → awaiting_approval → approved|rejected|failed` (`continue`/`revise` 결정은 다시 running).
- 연속 운영 가드: 세션 예산(시작 때마다 새 예산), 승인 대기 건수 backpressure(`max_pending`), 연속 3회 실패 자동 정지, 동시성 1~4, **프로세스 시작 시 항상 정지 상태**, 재시작 시 좀비 running run 정리, Office의 재개가 예산/실패 상한을 우회하지 못하게 `resume`은 수동 정지 뒤에만.
- 단계 승인 모드: 라운드마다 멈춰서 사람이 계속/승인/반려. 라운드 상한은 적용 안 함(사람이 멈출 시점을 정함), 예산 가드는 우선.

## 4. 결정 로그

| 결정 | 대안 | 이유 |
|---|---|---|
| Office 시각화를 목적이 아니라 Ops의 한 화면으로 | 오피스 시뮬레이터 자체를 제품으로 | 실체가 에이전트 운영/관측/검증이라 시각화는 의사결정자용 뷰로 충분 |
| 연속 운영은 큐 + 워커 | 무한 루프, 외부 스케줄러 | 사람 승인과 비동기로 분리하고 가드(예산/backpressure/연속실패)를 한 곳에 둘 수 있음 |
| 자동 승인 없음(기본) | 점수 통과 시 자동 확정 | "AI는 확정 못 함" 원칙. 5장 허위 사례가 근거 |
| 비용 = 토큰 × 단가를 직접 계산 | 응답의 비용 필드 사용 | 게이트웨이 응답에 비용이 없음. 대시보드 값과 교차 검증으로 신뢰 확보 |
| 저장소를 JSONL → **SQLite 단일 파일** (2026-11-26) | 하이브리드(라이브러리만 DB), JSON 파일 | "프롬프트 버전별 성과 비교" 같은 교차 분석이 핵심 기능이 될 것. 저장소 접근이 store 인터페이스에 모여 있어 이전 비용이 작았음 |
| 불변성을 DB 트리거로 (`events`/큐 UPDATE·DELETE 거부) | 코드 규율에 의존 | JSONL의 "사후 수정 불가"를 DB 제약으로 옮겨 오히려 강화 |
| 데이터는 이 저장소에 커밋하지 않음 | .db 직접 커밋, 저장소 비공개 전환 | 공개 저장소(포트폴리오 가치)는 유지하고 개인 데이터만 분리. 별도 관리 방식은 결정 대기 |
| 이전/백업은 결정적 텍스트 내보내기 | .db 바이너리 복사 | diff·merge 가능, 멱등 import, 내보내기는 절대 삭제 안 함 |
| 프롬프트는 `{{변수}}` 템플릿 + **버전 불변** (2026-11-26) | `str.format`, 덮어쓰기 편집 | 리뷰어 프롬프트에 JSON 예시 중괄호가 있어 `format`은 충돌. 불변 버전이어야 "v2가 v1보다 나았나"를 run과 연결해 비교할 수 있음 |
| 편집 가능한 부분과 **코드 고정 부분 분리** | 프롬프트 전체를 편집 가능하게 | 지어내기 금지 규칙, 글자 수 문구, 리뷰어 JSON 형식은 편집으로 빠지면 안전·파싱이 깨짐. 화면에는 읽기 전용으로 보여줌 |
| run은 프롬프트 **본문 + `이름@버전`을 복사** | 참조(ID)만 저장 | 라이브러리를 고치거나 지워도 과거 run이 재현됨. 큐 작업도 등록 시점 본문을 가짐 |
| 필수 변수·미지 변수 검사를 저장 때와 실행 때 **같은 함수로** | 화면에서만 검사 | 저장된 프롬프트는 항상 실행 가능하고, 손으로 쓴 `overrides.prompts`도 같은 검사를 통과해야 함 |
| 데이터셋 항목 가져오기는 전체 성공 또는 전체 취소 | 정상 행만 반영 | 어느 행까지 들어갔는지 모르는 상태가 가장 나쁨. 오류는 행 번호로 알려줌 |
| 리소스는 **글자만 저장**하고 화면에서 교정하게 함 (2026-11-26) | 원본 파일 보관, 추출 결과를 그대로 신뢰 | PDF 추출은 틀릴 수 있고 이 글자가 자소서의 "근거"가 됨. 원본 PDF를 안 두면 개인정보 사본도 줄어듦 |
| 인코딩은 UTF-8 → EUC-KR 순으로 시도하고 **둘 다 아니면 거부** | `chardet`류 추측 | 틀리게 추측한 한글이 근거로 들어가는 것이 거부보다 나쁨. 거부 문구에 해결 방법을 적음 |
| 스캔본 PDF는 **이유와 함께 거부** (지금) | 조용히 빈 텍스트 저장, 바로 OCR | 글자가 없는 리소스가 "근거 없음"으로 조용히 들어가는 걸 막음. 이미지→텍스트(비전)는 M2에서 같은 경로로 붙일 수 있음 |
| 업로드는 base64를 담은 JSON | multipart | `python-multipart` 의존성이 없고, 한 요청 = 한 파일이라 오류를 파일별로 보고하기 쉬움 |
| PDF는 확장자가 아니라 **내용(`%PDF-`)으로도 판별** | 확장자만 신뢰 | 이름을 잘못 붙인 파일도 같은 규칙(스캔본 판별 등)을 거치게 함 |
| 리소스는 **DB에 유지**하고 "들고 다니지 않게" 잠금 (2026-11-26) | 파일 폴더 방식으로 교체 | 문제는 저장 위치가 아니라 데이터가 어디로 가느냐였음. 이력서 내용은 프롬프트로 실행 기록에도 들어가서 리소스만 DB 밖에 둬도 경계가 안 됨. 대신 git 무시·내보내기 거부·잠금 테스트로 이동 경로를 막음. 원본 PDF·이미지는 저장하지 않음 |
| PDF 변환은 **쪽 단위: 글자 층이 정상이면 무료, 아니면 LLM** | 항상 LLM | 글자 층 추출은 무료·정확. LLM은 비용이 들고 "옮기면서 고칠" 위험이 있음. 깨진 글자 층(한글 문서 변환 PDF에서 흔함)은 정상처럼 보이므로 코드가 판별해야 함 |
| LLM 변환 결과는 **검수 전 → 사람 확인 후**에만 근거로 사용 | 표시만 하고 바로 사용 | 잘못 옮긴 수치가 "근거 일치" 가드까지 통과해 버리는 것을 막음 |
| 워크플로가 `input_fields`·`prompt_roles`를 **선언** | 화면에 자소서 필드를 하드코딩 | 두 번째 워크플로가 같은 라이브러리 화면을 재사용하게 하려는 포석 (화면 폼 자체는 아직 자소서 전용) |

## 5. 실측과 수치 (2026-11-26, 사내 게이트웨이, 소액)

- 대시보드와 로컬 집계 일치 검증: 입력 1272 / 출력 550 토큰 = $0.008044, 14 / 4 토큰 = $0.000034 를 단가 역산 후 정확히 재현. 처음엔 기본 단가(3/15 USD per 1M)를 써서 비용이 과대 추정됨 → 대시보드에서 역산한 `pricing.json`으로 교체.
- 단계 모드 실제 시험 1건: 6콜, 입력 4,793 / 출력 2,773 토큰, **$0.028** (예산 상한 $0.10의 28%). 모델별로 reviewer(고가 모델)가 비용의 약 2/3. 실패 콜 0.
- **LLM 점수만으로는 허위를 못 거른다.** 입력 초안은 한 줄뿐인데 writer가 "500GB 로그 ETL, Spark로 8시간→2시간, 오류율 93%→2%"를 지어냈고, reviewer는 이를 "수치가 구체적"이라며 높게 채점 (4.2 → 7.55 → 7.65). 같은 결과물이 500자 제한에 527자였는데 reviewer는 분량 항목에 8점.
- 조치 후 재시험(같은 입력·코멘트): 지어낸 내용 없음(빈칸으로 표시), 분량 초과 라운드는 코드가 측정한 문구를 받아 다음 라운드에 329자로 감소. 점수는 2.25 → 2.4 → 3.9 로 **정직하게 낮아짐**(구체성 부재). 점수가 오르는 것과 사실에 부합하는 것은 다르다.
- 테스트 122개. 핵심 로직은 의도적으로 꺼보는 변이 검사로 테스트가 잡는지 확인(예산 가드, backpressure, 예산 상한, 단계 정지, 추가 전용 트리거, 실행 시 템플릿 검사, run의 프롬프트 복사, 고정 가드 규칙).
- 기본 템플릿이 기존 하드코딩 프롬프트와 **글자 그대로 같은지** 고정(golden) 테스트로 확인 → 템플릿화 전후로 기존 테스트 106개가 수정 없이 통과.
- 리소스(M1): 테스트 13개 추가(총 136). 한글 PDF·"글자 없는 PDF" 픽스처는 Chrome으로 생성(내용은 가상). 변이 검사 2종(EUC-KR 대체, 스캔본 판별)을 테스트가 잡음. 브라우저 E2E 12개 통과 — 실제 끌어놓기 이벤트, 스캔본 거부, EUC-KR 파일, 교정 저장, 빈 저장 거부, 붙여넣기, 삭제.
- 라이브러리 브라우저 E2E 20개 항목 통과(데이터셋 생성·항목 추가/수정/삭제·CSV 가져오기와 전체 취소·프롬프트 버전 저장/검증 거부·폼에 불러오기·고정 버전으로 실행·큐 등록 스냅샷).
- 한계: 1인 로컬 도구, 실제 LLM 시험은 소액 몇 건. 수치는 이 프로젝트 안에서만 의미.

### 게이트웨이 능력 점검 (2026-11-26) — 계획은 `plan-task-pipeline.md`

- 이미지 입력 지원(한글 OCR 글자 그대로 일치, ≈ $0.0004), 웹 검색 도구 지원(검색을 강제해야 실제로 검색함).
- **검색 1회가 입력 토큰 약 18,900개를 붙임**(≈ $0.02). 호출 전 예산 가드는 프롬프트 길이만 보고 추정하므로, 도구가 가져오는 토큰은 못 봄 → 회사 조사 단계에서 검색 허용 몫을 최악 추정에 더해야 한다. 계측이 우회되지 않게 하겠다는 원칙이 새 기능(도구 사용)에서 구멍이 날 수 있는 지점을 구현 전에 발견.
- PDF 직접 전송 지원(`document` 블록): 글자 있는 2쪽 PDF와 **그림만 있는 PDF** 모두 글자 그대로 일치. 각 $0.0039 / $0.0018. 쪽 렌더링 라이브러리 불필요.
- 점검 비용이 내가 예고한 한도($0.01)를 넘음(≈ $0.023): 검색 결과 토큰 규모를 사전에 몰랐고, 한도를 넘긴 사실은 바로 보고함. 교훈: 도구 호출 비용은 미리 크게 잡아서 말한다.

## 6. 사고·버그와 교훈

- **내 테스트가 실제 `.env`를 읽어 실제 게이트웨이를 1회 호출** (≲ $0.02). 대시보드를 보고 알아챔 → 테스트 전역 fixture로 게이트웨이 환경변수 제거, 사용자에게 바로 공개. 교훈: 테스트도 외부 비용을 만들 수 있다. 환경을 읽는 모듈은 임포트만으로 자격증명을 로드한다.
- 게이트웨이 401인데 본문이 비어 원인 파악이 어려웠음 → 기본 URL에 `/messages` 경로가 빠져 있었음. URL이 `/messages`로 안 끝나면 자동으로 붙임.
- `append()`가 `run_id`를 키워드로 받아 "multiple values for argument 'run_id'" → 이벤트 데이터에 `run_id` 필드가 있어서 충돌. 위치 전용 인자(`/`)로 해결.
- 한글을 셸 curl 본문으로 보내면 깨짐 → 파이썬 클라이언트 + UTF-8 강제. 출력은 파일로 리다이렉트(타임아웃 시 파이프 출력 유실 방지).
- 브라우저 자동화: 헤드리스 CLI는 정책으로 막혀 Playwright + 시스템 Chrome 사용. 해시만 바뀌는 이동에서 run 재선택이 안 돼 `hashchange` 처리 추가. iframe 안에서 Esc가 안 먹어 Ops가 부모로 close 메시지를 보냄.
- 내보내기에 "DB에 없는 run 파일 삭제" 로직을 넣었다가, 빈 DB로 내보내면 이미 보관한 데이터를 지울 수 있다는 걸 스스로 발견하고 제거. 내보내기는 추가/덮어쓰기만.
- SQLite 행 단위 트리거는 빈 테이블 DELETE에는 안 걸림 → 테스트는 먼저 행을 넣어야 검증됨.
- DB는 파일을 열어두므로 "서버 켜진 채 폴더 삭제" 시나리오는 Windows에선 삭제 자체가 막히고 리눅스에선 지운 파일에 조용히 계속 씀 → 해당 테스트 제거, 초기화는 서버 끄고 DB 삭제로 문서화.
- 셸 here-doc으로 파이썬 코드를 넘기다 이스케이프(`\n`)가 꼬여 파일이 깨짐 → 되돌리고 편집 도구로 재적용. 코드 수정은 편집 도구, 스크립트는 파일로. **같은 실수를 한 번 더 함**(라이브러리 작업 중 `cover_letter.py`): 백슬래시가 든 코드는 here-doc/`sed`로 고치지 않는다. `sed` 변이 검사도 같은 이유로 조용히 적용이 안 돼 "통과"가 나옴 → 변이는 적용됐는지 먼저 확인하고, 안 되면 편집 도구로.
- **시각을 초 단위로 저장해서 "더 최근 수정본이 이긴다"가 깨짐**: 가져오기에서 항목은 `updated_at`이 더 클 때만 덮어쓰는데, 초 단위라 같은 초 안의 수정은 새 것으로 인식되지 않았음. 테스트(수정 직후 다시 내보내기)가 잡아줬고 밀리초로 변경. 교훈: 비교에 쓰는 타임스탬프는 해상도부터 정한다.
- 서로 다른 PC에서 같은 `이름@버전`에 다른 본문을 저장하면 조용히 한쪽이 무시되는 문제를 설계 단계에서 짚음 → 가져오기를 실패시키고 이유를 알려줌(불변 버전의 약속을 지키는 쪽).
- 브라우저 E2E: 임시 데이터 폴더로 별도 서버(8766)를 띄워 실제 DB를 건드리지 않고 검증. 의도적으로 보낸 잘못된 입력 3건의 400 응답이 콘솔 오류로 잡혀 종료 코드가 1이 됨 → JS 오류와 구분해서 읽어야 함.

## 7. 경쟁력 포인트 (정직한 표현으로)

1. 비용 통제를 **호출 전 사전 차단**으로 설계하고 게이트웨이 대시보드와 교차 검증.
2. 사람 결정으로만 닫히는 루프 + 연속 운영 안전장치(예산·backpressure·연속 실패·재시작 시 정지).
3. LLM 평가의 한계를 **실측으로 확인**하고, 측정 가능한 제약은 코드로, 나머지는 사람 게이트로 보완.
4. 모든 화면이 이벤트 로그에서 파생돼 재현·비교 가능. 추가 전용은 DB 제약으로 보증.
5. 인터페이스 경계를 먼저 그어서 저장소 교체(JSONL → SQLite)가 파일 2개 수정으로 끝남.
